Language support (#trans)
=========================

Language-tagged literals carry their lowercase language tag through SQL
expression metadata. The /sparql endpoint preserves tags in JSON, XML and TSV;
CSV returns only the text. Translation records are not expanded into rows.

Zotonic translation functions
-----------------------------

zotonic:translation(Value, Language)

    Select the exact language from a #trans{} value. Missing translations are
    unbound. Normalize the requested code to lowercase, but do not expand
    aliases or parent languages.

zotonic:translationFallback(Value, Language)

    Canonicalize the requested language using Zotonic's aliases, then try its
    z_language:fallback_language/1 chain, the site default, English, and any
    available translation. For example, nl-nl tries nl before the site default;
    zh-tw resolves to zh-hant, whose configured fallback includes zh.
    This follows z_trans:lookup_fallback/3 given the canonical language and its
    chain. The final arbitrary choice uses language-code order because JSONB
    does not preserve the original translation-list order.

Both functions accept stored #trans{} values, JSONB strings, text/varchar
columns, string expressions and nulls. Plain strings stay untagged. Null or
missing values remain unbound; empty strings are existing values. Tagged
literals retain their language and are matched accordingly. Results carry
the actual selected language, including when fallback selects another language.
Unknown codes have no fallback translation; plain strings remain unchanged.

The Language argument may be a literal, a pre-bound args value, or a row
variable. Both functions execute in SQL and compose with COALESCE, ordering
and DISTINCT. They do not translate text or multiply result rows.

Example
-------

    SELECT ?s
           (zotonic:translation(?title, "en") AS ?title_en)
           (zotonic:translationFallback(?title, "nl-nl") AS ?title_nl)
    WHERE {
        ?s zotonic:is_published true .
        OPTIONAL { ?s zotonic:title ?title }
    }

For explicit fallback, use:

    COALESCE(zotonic:translation(?title, "nl"),
             zotonic:translation(?title, "en"), "Untitled")

Selecting ?title directly on /sparql still performs context-language fallback
after SQL filtering, grouping, ordering and pagination.

Versioned SQL helpers
---------------------

Module schema version 2 installs helpers from zotonic_mod_sparql/priv/sql:

- z_sparql_translation_v1: exact lookup.
- z_sparql_translation_v2: lookup with Zotonic's fallback chain.
- z_sparql_language_chain_v2: registry generated from z_language_data at install.

Translation helpers have JSONB and text overloads and return a JSONB object
with value and optional language, or SQL NULL. The compiler projects text and
RDF metadata separately. Helpers do not fetch resources or site configuration;
property ACL checks remain in the normal query pipeline.

For helper or registry changes, add a new numbered helper, bump mod_schema,
install the new version and update the compiler. Retain earlier versions while
older code or queries may still use them.

Standard language functions
---------------------------

LANG, LANGMATCHES and STRLANG remain unsupported. DATATYPE supports the existing
RDF metadata, including rdf:langString for translation-function results;
heterogeneous aggregate metadata remains limited.
