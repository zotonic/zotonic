Parametrized SPARQL
===================


We want to prevent SPARQL injection attacks by adding parameters to the SPARQL queries.

These parameters might be pre-bound values. In this way we can parametrize every spot
where a constant or an IRI is used.

Discussions:

https://web.archive.org/web/20150512231123/http://answers.semanticweb.com/questions/12147/whats-the-best-way-to-parameterize-sparql-queries

Many implementations use a dynamic way to build SPARQL with arguments. By concatenation and
escaping the arguments manually.

Looks like the method of pre-binding the arguments to variables is the way to go.
In this way we could supply a map of arguments, which is then used by the SPARQL planner.
This prevents any need for escaping, as the SQL mapper already uses PostgreSQL bindings
for all values in the SPARQL query.

Questions:

1. Types. We might need to add type hints for IRIs?  Numeric and boolean arguments are clear.
2. Should we be able to pass JSONB structured objects  (why not?)


Solution
========

We can use the 'VALUES' SPARQL feature to bind the arguments to their values. As if extra
VALUES clauses are added to the query.

For example:

    PREFIX zotonic: <http://zotonic.net/predicate/>
    SELECT ?r ?title
    WHERE {
        ?r zotonic:is_published ?published .
        ?r zotonic:date_start ?date_start .
        ?r zotonic:relation ?related .
        ?r zotonic:title ?title .

        FILTER (?date_start >= ?since)
    }

With arguments:

    #{
        <<"published">> => false,
        <<"since">> => {{2008, 12, 10}, {0, 0, 0}},
        <<"related">> => {rsc, RelatedId}
    }

The query can be executed with:

    z_sparql:search(Sparql, Arguments, Context)

Or, with explicit pagination:

    z_sparql:search(Sparql, Arguments, {1, 20}, Context)

Argument names can be binaries or atoms, atoms are converted to binaries.
All atom values (except 'true', 'false', and 'undefined') are converted to binaries.
The value 'undefined' is mapped to SPARQL 'UNDEF', which is an unbound variable.

This would then be as if the following query was written:

    PREFIX xsd: <http://www.w3.org/2001/XMLSchema#>
    PREFIX zotonic: <http://zotonic.net/predicate/>
    SELECT ?r ?title
    WHERE {
        VALUES ?published { false }
        VALUES ?since { "2008-12-10T00:00:00Z"^^xsd:dateTime }
        VALUES ?related { <https://example.test/id/123> }

        ?r zotonic:is_published ?published .
        ?r zotonic:date_start ?date_start .
        ?r zotonic:relation ?related .
        ?r zotonic:title ?title .

        FILTER (?date_start >= ?since)
    }

So we add the values, and the namespace (if needed).
